# Что передать команде

Поддержка макета на уровне БД добавлена миграцией 003:
project, duration_minutes (минуты), new/progress/blocked, общий user_profiles.timezone.
Старые значения, UUID и имена столбцов сохраняются. 001/002 не изменялись.

Для API создана отдельная роль assistant_api, пароль STACK_API_PASSWORD.
Она может создавать/читать/удалять события и менять status, но не user_id/id/DDL.
MCP остаётся на assistant_app с SELECT/INSERT — расширять права LLM ради UI не нужно.
Готовые Python-функции находятся в app/api_storage.py; HTTP-роуты они не регистрируют.

Разработчику API/Mini App остаётся:

- Подключить API к assistant_api, реализовать/проверить /api/tasks и PATCH/DELETE.
- Адаптировать title↔name, desc↔description, dur↔duration_minutes и date/time↔event_at.
- Передавать UUID строкой, убрать преобразования ID в число в JavaScript.
- Согласовать reminder/cancelled и отображение legacy pending как new.
- Получать доверенный user_id и применять авторизацию перед операциями.

Владельцу бота/API: перенести существующие пояса из SQLite и затем сохранять
их в user_profiles. API без профиля не должен считать всех пользователями Москвы.
Если нет timezone, нужно уточнение; для DST неоднозначности требуется точное смещение.

Обновление существующей установки — обычный запуск start.ps1/start.sh: новый
пароль API добавится автоматически, прежние пароли и volume сохранятся.
Не удалять БД и не заменять миграции 001/002. Подробнее — MINI_APP_CONTRACT.md.

Проверены 41 тест и чистая установка из архива, включая сохранение после restart
PostgreSQL. Реальный Mini App, HTTP API и SQLite отсутствуют в этой копии:
их исходники и интеграция не проверены. Нельзя утверждать, что frontend уже состыкован.
