# MAX-бот — «Горький код»

Готовый транспортный модуль команды: принимает текст и голос, передаёт запросы
AI-агенту, отвечает пользователю и доставляет зарегистрированные напоминания.
Python 3.11+. Основной код не требует сторонних библиотек.

Это модуль `max-bot/`, а не вся система ассистента. Понимание естественной речи,
создание/поиск задач, PostgreSQL и контекст уточняющего диалога реализует команда
агента и данных. Здесь есть HTTP-клиенты к этим сервисам и явные контракты.
Встроенная SQLite хранит транспортную очередь, настройки и доставку уведомлений.

## Что реализовано

- `/start`, `/help`, примеры четырёх основных сценариев.
- Приём свободного текста и аудиовложений `audio` в личном диалоге.
- Скачивание аудио только с настроенных HTTPS-хостов, ограничение размера;
  передача на STT через multipart. Аудио находится в памяти, файлов не создаёт.
- Кнопки «Сегодня», «Завтра», «Помощь» и ссылка на зарегистрированное Mini App.
- Команды `/today`, `/tomorrow`, `/app`, `/timezone Europe/Moscow`.
- Стабильный `conversation_id` для уточнений и `message_id` для идемпотентности.
- Передача текущей даты и пользовательского часового пояса агенту.
- Сообщение «Обрабатываю запрос…», понятные ответы при сбоях STT и агента.
- Деление длинного ответа, ограничение частоты исходящих сообщений.
- Durable webhook inbox: HTTP 200 только после сохранения события в SQLite.
- Дедупликация событий между перезапусками, сохранение ответа агента перед
  доставкой, повторные попытки отправки с задержкой (до 5 попыток).
- Отправка напоминаний по времени, сохранение их состояния между перезапусками.
- Проверка секрета webhook и ключа внутреннего API; токены не пишутся в логи.
- Polling для разработки; webhook для размещения, `/health` для проверки процесса.
- Dockerfile, Compose и тесты стандартным `unittest`.

## Быстрый запуск на Windows

1. Перенесите эту папку целиком в `max-bot/` вашего клонированного репозитория.
2. Откройте терминал в этой папке и проверьте Python:

```powershell
py --version
Copy-Item .env.example .env
```

Если команды `py` нет, используйте `python`. Нужен Python 3.11 или новее.

3. Откройте `.env`, заполните `MAX_BOT_TOKEN`. Пока агент не готов, оставьте:

```dotenv
AGENT_MODE=mock
```

4. Запустите:

```powershell
py bot.py polling
```

5. Откройте своего бота в MAX, нажмите старт, отправьте текст и нажмите кнопки.

**Mock проверяет только работу транспорта. Он прямо пишет, что ничего не сохранил.**
Для реального выполнения четырёх сценариев подключите HTTP-агента ниже.
Для реального голосового ввода отдельно подключите STT.

`.env` содержит секреты: не загружайте его в публичный GitHub.
В папке уже есть `.gitignore`, который исключает `.env` и `state/`.
Не запускайте два процесса на одном файле состояния: поддерживается один экземпляр.

## Подключение агента — контракт для участника №3

В `.env`:

```dotenv
AGENT_MODE=http
AGENT_URL=http://127.0.0.1:8001/chat
AGENT_API_KEY=your-internal-secret
```

Бот делает `POST AGENT_URL`, передавая `Authorization: Bearer ...` (если ключ задан)
и `Idempotency-Key: message:m1`:

```json
{
  "user_id": "123",
  "message_id": "message:m1",
  "conversation_id": "max:123",
  "text": "Встреча с Иваном завтра",
  "timezone": "Europe/Moscow",
  "now": "2026-10-24T12:00:00+03:00"
}
```

Ответ HTTP 200:

```json
{"reply": "На какое время поставить встречу?"}
```

Следующий текст «В три» придёт с тем же `conversation_id` и новым `message_id`.
**Контекст хранит агент**, например в Redis. Бот не пытается самостоятельно
интерпретировать даты и не заменяет бизнес-логику агента.

Агент должен выполнять четыре сценария: создание задачи/напоминания, создание
встречи, список за период, поиск старых записей. `reply` после создания должен
подтверждать действие только после успешной записи в PostgreSQL.

Агент обязан проверять внутренний ключ, ограничивать операции `user_id` и хранить
результат по `Idempotency-Key` вместе с бизнес-операцией. Если запрос оборвался
после записи, повтор с тем же ключом возвращает прежний результат. Новый запрос
пользователя имеет новый ключ: при неясном результате сначала проверьте список
задач, прежде чем создавать ещё одну. Ответ от агента кешируется в inbox бота
перед отправкой в MAX.

Не возвращайте произвольный `user_id`: бот всегда выбирает адресата по событию MAX.

## Голос — контракт STT

Настройте `.env`:

```dotenv
STT_URL=https://your-speech-service.example/v1/audio/transcriptions
STT_API_KEY=your-speech-key
STT_MODEL=whisper-1
AUDIO_ALLOWED_HOSTS=exact-audio-cdn-host.example
```

Это пример формы настройки, не существующий сервис. Укажите свой провайдер или
собственный Whisper-совместимый endpoint. Название модели зависит от сервиса.
Реализация не привязана к конкретному поставщику.

STT получает multipart: `file` (байты аудио), `model`, `language=ru`.
Если задан ключ, бот добавляет `Authorization: Bearer STT_API_KEY`.
Сервис должен вернуть HTTP 200 и `{"text":"Распознанная фраза"}`.
Сырые Yandex/SpeechKit и другие API с другим форматом требуют отдельного адаптера.

`AUDIO_ALLOWED_HOSTS` — точные имена CDN из `attachments[].payload.url`
реальных событий вашего MAX-бота, через запятую. Не копируйте полный подписанный
URL в публичные логи/репозиторий. До настройки хостов голос безопасно отклоняется.
Перенаправления при скачивании запрещены; если CDN сменился, обновите allowlist.
Не добавляйте туда внутренние адреса и сервисы.

Аудио ограничено 20 МБ; можно изменить `MAX_AUDIO_BYTES`. Временные аудиофайлы
не создаются. Распознанный текст и события находятся в транспортной SQLite:
файл состояния содержит пользовательские данные, храните его приватно.

## Mini App — контракт для участника №2

Попросите разработчика интерфейса привязать приложение к боту в платформе MAX
и передать проверенную ссылку открытия приложения. Укажите её в `MINI_APP_LINK`.
Бот выводит кнопку-ссылку; простого URL на React-сайт недостаточно, чтобы
зарегистрировать Mini App в MAX. Авторизацию Mini App проверяет его HTTP API.

## Напоминания — контракт для участника №5

Предпочтительно агент возвращает напоминания вместе с результатом создания:

```json
{
  "reply": "Напомню завтра в 10:00 позвонить Ивану",
  "reminders": [
    {
      "id": "record-42-reminder-1",
      "text": "Позвонить Ивану",
      "due_at": "2026-10-25T10:00:00+03:00"
    }
  ]
}
```

Бот берёт получателя из исходного события. ID должен быть стабильным, уникальным
для уведомления. Повторная регистрация такого же ID не создаёт дубль и не сбрасывает
отметку отправки. Другой текст/получатель/время с тем же ID отклоняется.
Дата без часового пояса отклоняется. Просроченные уведомления отправляются при запуске.

Либо в webhook-режиме сервис данных вызывает `POST /internal/reminders`:

```http
Authorization: Bearer значение_INTERNAL_API_KEY
Content-Type: application/json
```

```json
{
  "id": "record-42-reminder-1",
  "user_id": 123,
  "text": "Позвонить Ивану",
  "due_at": "2026-10-25T10:00:00+03:00"
}
```

Задайте `INTERNAL_API_KEY`, иначе endpoint закрыт. Он доступен только доверенному
сервису данных: не вызывайте его из браузера Mini App. При HTTP 200 регистрация
сохранена. Сервис данных должен повторять неуспешную регистрацию с тем же ID.
В polling-режиме HTTP-сервер не запускается; используйте поле `reminders` агента.

## Ошибка CERTIFICATE_VERIFY_FAILED

Если проверка цепочки сертификата API MAX не проходит:

1. Официальная страница сертификатов: https://www.gosuslugi.ru/crt.
2. Скачайте PEM корневого сертификата с официального адреса
   https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt.
3. Сохраните файл в папку рядом с `bot.py`.
4. В `.env` задайте `EXTRA_CA_FILE=russian_trusted_root_ca_pem.crt`.
5. Перезапустите бота. Относительный путь считается от папки `bot.py`.

Не сохраняйте вместо сертификата HTML-страницу. Файл PEM начинается строкой
`-----BEGIN CERTIFICATE-----`. Если браузер отказывается проверять сертификат
самого сайта загрузки, используйте официальную инструкцию Госуслуг; не отключайте
проверку TLS. Системное хранилище Windows при данном способе не изменяется.
Если проблема остаётся, проверьте дату компьютера и влияние VPN/прокси/антивируса.

## Часовой пояс

По умолчанию Europe/Moscow. Пользователь может отправить `/timezone Asia/Yekaterinburg`.
Для произвольных IANA-зон на Windows установите данные часовых поясов:

```powershell
py -m pip install -r requirements.txt
```

Москва и UTC работают без сторонних зависимостей. Время передаётся агенту,
а напоминания хранятся как абсолютные моменты времени.

## Webhook на сервере

1. Задайте `WEBHOOK_SECRET` (случайные 32+ символа: буквы, цифры, `_`, `-`).
2. Задайте `WEBHOOK_URL=https://your-domain.example/webhook`.
3. Запустите `py bot.py webhook` или `docker compose up --build -d`.
4. Настройте HTTPS reverse proxy: публичный порт 443 -> локальный 8080.
   Пропускайте `/webhook` и при необходимости `/health`; не публикуйте
   `/internal/reminders` наружу. Ограничьте размер тела до 1 МБ.
5. Зарегистрируйте подписку: `py bot.py subscribe`.
6. Проверка локального процесса: `http://127.0.0.1:8080/health`.

MAX требует публичный HTTPS endpoint с доверенным сертификатом и портом 443.
Если для исходящих запросов нужна дополнительная доверенная CA-цепочка, задайте
путь `EXTRA_CA_FILE`. Проверка TLS никогда не отключается.

Вернуться к локальному polling: `py bot.py unsubscribe`, затем `py bot.py polling`.
Polling при активной webhook-подписке запрещён: бот проверяет это при запуске.
В Docker `AGENT_URL` должен указывать на имя сервиса команды или доступный адрес,
а не `127.0.0.1` соседнего контейнера. Сохраняйте том `bot-state` между обновлениями.

## Проверка

Из этой директории:

```powershell
py -m unittest discover -s tests -v
```

15 тестов: защита webhook, durable inbox, дедупликация после перезапуска,
кнопки и callback, изоляция получателя, контекст, ошибки, STT multipart,
запрет посторонних audio URL, длинные ответы, повторная доставка,
идемпотентная регистрация напоминаний и даты с часовым поясом.
HTTP-вызовы MAX/STT/агента в тестах заменены заглушками; webhook проверяется
через настоящий локальный HTTP-сервер. Токен MAX для тестов не требуется.

## Границы прототипа

- Реальный MAX, STT и агент нужно проверить с вашими ключами перед демонстрацией.
- Запускайте один экземпляр и один worker. Длинный STT/запрос агента временно
  задерживает другие запросы и напоминания. Для нагрузки нужны раздельные workers
  и блокировки по диалогам; текущий вариант рассчитан на командный прототип.
- За 5 неудач отправки работа переводится в завершённую с записью `job_failed`
  в журнале; напоминание с 5 неудачами остаётся в таблице для ручного разбора.
  Перед демонстрацией проверяйте журнал и `attempts` в SQLite.
- Абсолютно однократная доставка в MAX не гарантируется: если MAX принял сообщение,
  а соединение оборвалось до ответа или процесс упал до локальной отметки, при
  повторе возможен дубль ответа/уведомления. Повторного вызова агента после
  сохранения ответа бот не делает. Бизнес-идемпотентность обеспечивается агентом.
- Изменение/удаление, отмена и перенос уже зарегистрированного напоминания,
  повторы, конфликты и TTS не включены: это дополнительные возможности.
- Для production добавьте очистку старых событий, мониторинг очереди, резервное
  копирование, распределённые блокировки и процессы повторного разбора ошибок.
