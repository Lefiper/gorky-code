# Подготовка к передаче и публикации

В репозиторий входят код, Docker-конфигурация, миграции, зависимости, тесты,
документация и синтетические планы запросов. .env, .env.docker, .venv, dist
исключены через .gitignore; Docker-сборка также не включает секреты.

## Передача без Git

```powershell
.\.venv\Scripts\python.exe -m scripts.package_release
```

Получится dist/assistant-storage-mcp.zip и SHA256SUMS.txt. Архив можно передать
команде или использовать для загрузки исходников. В нём только исходники:
при первом запуске нужны Docker и интернет для скачивания образов/пакетов.
Не архивируйте всю рабочую папку вручную: там есть локальные настройки.

Автоматическая независимая проверка архива в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_release.ps1
```

Она распаковывает архив в отдельную папку внутри dist, создаёт свои пароли,
контейнеры и новый volume, запускает тесты и проверяет сохранение после restart
PostgreSQL. Использует порты 55433/6381/18001. В конце тестовый стек останавливается;
его файлы и volume не удаляются. Основной стек и локальный PostgreSQL не меняются.
Отчёт — docs/reports/fresh_install.json.

## GitHub

GitHub-репозиторий ещё не создан, адрес remote не задан. Публикация в этой работе
не выполняется: исходники подготовлены локально. После создания пустого командного
репозитория можно использовать обычные git-команды из корня проекта:

```sh
git init -b main
git add .
git status --short
git diff --cached --stat
```

Убедитесь, что .env/.env.docker отсутствуют в списке. Затем:

```sh
git commit -m "Add calendar storage, MCP tools and Redis memory"
git remote add origin <URL командного репозитория>
git push -u origin main
```

Если локальный репозиторий уже инициализирован, повторный init не нужен.
Если в командном репозитории уже есть код, не делайте push поверх него вслепую:
перенесите нашу часть отдельной веткой и согласуйте структуру app с backend.
Имя и email коммитера задаются пользователем локально, не выдумываются скриптами.
Лицензия намеренно не выбрана автоматически: согласуйте её с командой.

Подготовлен .github/workflows/check.yaml: после публикации он соберёт полный
Docker-стек с пустой БД и запустит тесты на Linux. На самом GitHub workflow пока
не запускался. Пароли в CI генерируются на месте; внешние аккаунты, LLM-ключи
и платные сервисы для тестов не нужны.
